先说目标和现实边界

这篇论文研究两个相反方向的化学预测：反应物 → 产物（反应预测）和 产物 → 可能的反应物（逆合成）。作者先用 BRICS 把分子拆成片段，再让同一模型学习“分子 → 片段”和“片段 → 分子”；随后训练两种反应方向。这里的“双任务”指两种输入输出方向，不是会调用工具、自主规划的 Agent。模型还扩展了 LLaMA 3.1 的 tokenizer。先读论文图 2、图 3、方法第 3 节和实验第 4 节即可，不必一开始读完所有公式。论文

  1. 链路验证：本地已有随机初始化小模型的一步 LoRA 训练、BRICS 和评估脚本通过。这只证明软件能跑。
  2. 方法级复现：用有来源且隔离测试集的数据，实际完成双方向数据构造、训练、预测、评估，并做单方向对照。若换了模型、词表或数据规模，就如实写“缩小规模复现”。
  3. 论文数值复现：在作者的数据划分、完整 tokenizer、LLaMA 3.1 8B、明确的训练配置与足够 GPU 上，重跑主要实验并对照论文表 1、表 2。当前不能承诺两周内达到这一层：仓库仍把训练数据和 ChemDual 权重标成 TODO，缺少完整 tokenizer 构建材料；你目前也没有 NVIDIA GPU。仓库

开始前要懂的 10 个词

词 先用这句话理解 自检问题
SMILES 把分子图写成一行文本；CCO 是乙醇的一种写法，. 隔开多个组分。 CCO 和 OCC 为什么可能指同一分子？
RDKit / 规范化 SMILES RDKit 把文本解析成分子并能输出统一写法；非法字符串可能无法解析。 Chem.MolFromSmiles 返回 None 时怎么办？
BRICS / 虚拟原子 按预设的化学键规则切分；[4*] 这类标记指示切口和可连接位置，不是普通碳原子。 一次切分如何产生“分子→片段”的训练对？
指令样本 / JSON 一条样本有任务描述、输入、目标输出；仓库数据是 instruction、input、output 字段。 哪个字段是模型应该生成的答案？
tokenizer / token 把字符串切成模型可处理的编号；SMILES 的一个字符未必等于一个 token。 增加 [4*] 这个 token 后词表大小是否变化？
SFT / 交叉熵 给模型正确答案，让它逐 token 预测；预测越偏离正确 token，损失越大。 训练 loss 下降能否直接证明测试准确率高？
LoRA 冻结大部分基础模型参数，只训练少量附加参数，节省训练显存。 为什么 LoRA 仍需要足够显存加载基础模型？
batch / 累积 / epoch batch 是一次处理的样本数；梯度累积把多批次的梯度合起来；epoch 是训练集完整走一遍。 2 卡、每卡 batch 2、累积 8 的有效 batch 是多少？（32）
数据泄漏 训练阶段看到测试答案或其等价表示，使评估失真。 同一反应的正、逆方向可否分别放入训练和测试？（不可）
Exact / Validity / 指纹相似度 分别问“答案是否完全相同”“预测能否解析成分子”“结构有多像”。 相似度高是否就代表反应答案正确？（不一定）
