4. JSON 一条“指令样本”长什么样：

5. 论文图 2 的四个方向（都用“输入 → 输出”记，这是整篇论文的坐标轴）：

DAY 2 · 10/16

SMILES 与 RDKit

今天目标：学会“用一行文本表示一个分子”，并用 RDKit 解析、画图、判断合法性。这是后面所有数据工作的地基——看不懂 SMILES，就看不懂训练样本。

这条线怎么串起来的：D1 你学会了读 JSON、知道了论文有"反应预测 / 逆合成 / 拆片段 / 拼分子"四个方向 → 今天 D2 学它们的共同语言：SMILES（分子怎么用一行文本表示）→ D3 就要用你今天的语法，把分子按 BRICS 规则"切积木"拆成片段。今天看不懂括号和环，D3 就拆不动。

学什么今天要懂的知识点（比昨天深一层，全部来自论文 3.1 节）

1. SMILES：把分子图写成一行文本，记住 5 条规则（这是”分子语言”的字母表）：

  • 原子：直接写元素符号。CCO 是乙醇；碳链连写 CCC。
  • 键：单键省略不写；双键 =、三键 #；芳香键用小写字母（苯环 c1ccccc1）。
  • 分支：用括号。CC(C)O 是异丙醇——中间的 C 分出一个小分支甲基。
  • 环：用闭环数字配对。C1CCCCC1 是环己烷：两个 1 之间连成环。
  • 多组分：用点 . 隔开，如盐 [Na+].[Cl-]。
乙醇 CCO 拆开看：C-C-O 三个原子连成一串，氢原子默认省略。它和 OCC 是同一个分子——SMILES 只是”按某种顺序遍历的写法”，顺序不同但读出来都是乙醇。

2. RDKit 两个核心函数——这俩就是论文数据流水线的”质检员”：

  • Chem.MolFromSmiles(“...”)：文本 → 分子对象；解析失败返回 None → 这条 SMILES 非法，不能当合法数据训练。
  • Chem.MolToSmiles(mol)：分子 → 规范 SMILES（唯一写法）。用途：去重。同一分子不管写成 CCO 还是 OCC，转成规范形式都一样——论文预处理第一步”removing duplicates（去重）”就是这么做的。

3. 为什么论文选 SMILES 当”语言”（论文 3.1 节数据预处理）：

  • LLM 只会读文本，不会看分子结构图。所以分子必须翻译成文本，SMILES 就是最通用的”分子文本”。
  • 论文从 ChEMBL 库拿到 20M 条 SMILES，然后三道预处理：去重 → RDKit 过滤无效分子 → 扔掉分子量 > 1000 的。最后得到 2.2M 分子库。
  • 你今天的 MolFromSmiles 练习，就是 2.2M 这条流水线上”过滤无效”那一步的缩小版。

4. 多组分 .：一个反应往往有多个分子（论文图 3 的 Input 例子）：

  • 论文里逆合成任务的输入长这样：CCCCC1CO1.Cc1ccc(C)c1.Cl.[Cl-]——三个点分隔了四个组分：一个环醚、一个芳香烃、氯气、氯离子。
  • 意思是”这个产物由这 4 个东西合成”。所以看到点 . 不是化学键，是”并列的一堆分子”。

5. 无效 SMILES = 训练毒药；VALIDITY 就是”能不能解析”（论文表 1 的 VALIDITY 列）：

  • 论文评估模型输出时，第一条硬指标就是 VALIDITY：把模型生成的 SMILES 交给 RDKit 解析，能解析 = 合法 = 算 1，解析失败 = 0。
  • ChemDual 反应预测的 VALIDITY 是 0.996，意思是生成的分子里 99.6% 能被 RDKit 认出来——这是”模型没在胡扯”的第一道证明。
  • 你今天第 2 步故意写 3 条无效 SMILES，就是在体验 VALIDITY 判 0 的那一刻。

6. 数据三字段 = 一条完整的”提问-回答”（论文图 3 的指令模板）：

  • 每条测试数据是 instruction / input / output：instruction 是提问模板，input 是给的材料，output 是标准答案。
  • 两个任务方向正好相反：正向 = 逆合成（给产物，问反应物）、反向 = 反应预测（给反应物，问产物）。这就是论文双任务学习要同时优化的”一对互逆任务”。

7. 预习：dummy atom（虚拟原子），明天 D3 的主角：

  • BRICS 把分子”切积木”时，切口处会留下一个记号 [4*] [5*]，叫 dummy atom（占位符）。比如 OCCCN1CCOCC1 切成 [4*]CCCO + [5*]N1CCOCC1。
  • 明天 D3 你就能看懂：切口记号 + 片段列表 = 分子的”拆解说明书”。今天先记住 [*] 长这样就行。

学什么今天要懂的知识点（核心来自论文 3.1 节 + 图 2(a)）

1. BRICS 是什么：Retrosynthetically Interesting Chemical Substructures——按“逆合成上有意义的键”规则切分子。像沿积木缝把分子拆成几块，断口都选在可逆反应的键上，拆出的块更接近真实合成子。

2. 虚拟原子 [4*] 是什么：切口的标记，表示“这里可以再接一块”，不是真实原子。片段带着这些“接头”，才能用于后面“片段→分子”的拼接任务。

论文图 2(a) 的原例：分子 NC(=O)CN1CCC(N)CC1 拆成 [4*]CC(N)=O 和 [5*]N1CCC(N)CC1 两个片段——[4*] [5*] 就是两个切口上的接头编号，一共 16 种（论文 3.2 节：[1*]~[16*]）。

3. 一次切分 = 一条“分子→片段”样本：输入完整分子，输出它的片段列表，这就是第一阶段训练数据的来源。反方向"片段→分子"就是重组——论文把"拆 + 拼"当成一对双任务同时训练（3.3 节，D6 会展开讲双任务）。

4. 重组时接头怎么处理（论文 3.1 节，防坑细节）：BRICS 在切口引入 dummy atom，论文重组时不额外处理 dummy atom，但拼接时会把这些接头[*] 替换成碳原子（C）——因为留着 * 拼出来的 SMILES 常常非法，换 C 才能保证生成的是合法分子。

5. 为什么能拿片段当训练数据（论文图 1(a) 的证据）：作者算了所有分子"拆出的片段 vs 真实反应物"的相似度，平均 66.5%——片段和真实反应物长得挺像，所以用片段练出来的能力能迁移到真实反应预测上。这就是"4.4M 便宜大数据替代昂贵实验数据"的底气。

6. 切太多会爆内存，所以自适应（论文 3.1 节公式 1）：长 SMILES 用 BRICS 会切出大量碎片导致内存溢出，作者按分子长度限制片段数：n = L（L<k 时），否则 n = min(L, ⌈L/k⌉^α)——L 是 SMILES 长度，k 是平均长度，α 是"弹性系数"（按机器内存调）。这个公式你复现时不用背，知道"长分子限制切分数量"这个意图就行。

7. 数据过滤（论文 3.1 节预处理三道关）：去重 → RDKit 过滤无法解析的 → 分子量 ≤ 1000 且 token 长度 ≤ 512。从 ChEMBL 的 20M 条筛到 2.2M 分子库。

8. 440 万条是怎么拼出来的（论文图 2(a) 全流程）：2.2M 分子库 → BRICS 拆+重组 → 套指令模板（"请给出反应物/请预测产物"，图 3）→ 得到 4.4M 条指令样本（一个分子拆出多个片段，样本数就翻倍了）。

9. 作者数据可得性：论文说代码和附录在 GitHub 开源，但作者训练数据在仓库仍是 TODO → 需要自己找独立数据源（USPTO、ChEMBL 等）走方法级路线（D7 定规格时会再碰这个问题）。

数据划分 + 防数据泄漏

今天目标：学会把数据分成训练/验证/测试三份，会成对构造正逆样本，并理解科研里最忌讳的“数据泄漏”——今天的内容直接决定你后面所有分数的可信度。

这条线怎么串起来的：D3 你造/找出了分子-片段样本 → 今天 D4 把这些数据分堆（训练/验证/测试）并学会防泄漏 → D5 学模型怎么"读"SMILES，分好的数据马上要喂给它。今天定死的划分规则，D8、D9 训练时都要遵守——分错了，后面所有分数都不可信。

学什么今天要懂的知识点

1. 三种划分：

  • 训练集：模型学习用。
  • 验证集：选超参数、看训练进度（可以反复看）。
  • 测试集：最终打分期——相当于“考生从没见过的考题”，只看一次，看完就不能再回头改模型。

2. 正逆样本成对构造：一个反应要生成两条样本——反应物 → 产物 和 产物 → 反应物，两个方向都要有（这正好对应论文的两个任务方向）。

3. 数据泄漏（最重要的一课）：训练时见过测试答案（或其等价表示）→ 测试分数虚高、不可信。类比：考试前把答案透给学生，考出来的高分没有意义。

核心规则：先按原始分子或反应 ID 划分，再生成正逆样本。同一反应的正、逆两个方向，绝不能一个进训练集、一个进测试集——那样等于漏题。

4. 随机种子：固定 seed 后划分结果可复现，别人照着跑能得到同样的切分。

5. 论文自己是怎么划分的（论文 4.1 节）：Mol-Instruction 是现成数据集，作者直接拿它微调（它自带反应指令）；USPTO-50K 则沿用 Graph2SMILES 的划分——复现时优先沿用作者/原始项目的 split，不要自己发明一套，否则分数没法跟论文比。

6. 正逆成对在论文里的样子（论文 3.3 节公式 2/3）：论文把数据写成 (M, F)/(F, M)（分子↔片段）和 (M, R)/(R, M)（产物↔反应物）两对——你今天"一个反应造两条样本"，造的就是 (R, M) 和 (M, R) 这两条。

7. 防泄漏 = 分数可信的入场券：论文表 1 每一个分数都建立在"测试集干净"的前提上。测试集里混进一条训练见过的反应，那个 EXACT 就是假的——这也是 D9 反复强调"公开测试 JSON 严禁进训练配置"的原因。

tokenizer 与词表扩展

今天目标：弄清模型是怎么“读”SMILES 的——tokenizer 把字符串切成什么、论文往词表里加了哪些化学 token，以及为什么加新 token 要配新参数。

这条线怎么串起来的：D4 分好的数据是纯文本 → 今天 D5 学模型第一步怎么处理文本：tokenizer 把 SMILES 切成小块、编号（论文还专门扩了化学 token）→ D6 这些编号进入训练循环被模型学习。今天搞不清"一个 token 是什么"，D6 的 loss 公式就看不懂。

学什么今天要懂的知识点

1. tokenizer 干什么（C 对照）：编译器词法分析把源码切成 token；这里把 SMILES 字符串切成模型能处理的最小单元，再转成编号喂给模型。

2. 一个字符 ≠ 一个 token：分词器会把常见子串（如 cc、(=O)）合并成一个 token，所以同一字符串切出的 token 列表和长度要看实际结果。

3. 论文往词表里加了什么（三个数字要记住）：

  • 16 个虚拟原子类型：BRICS 的 [4*] 等切口标记。
  • 180 个功能团：羰基、羧基等常见基团。作者未公开完整列表——不要自造一份冒充作者版本。
  • 4 个边界标记：<BOF>/<EOF>（分子起止）、<BOM>/<EOM>（片段起止）。论文图 2 与第 3.2 节对这两组标记的文字归属不一致，需要作者代码确认。

4. 为什么新 token 要配嵌入参数：每个 token 在模型里占一行 embedding 向量；词表变大 → 嵌入矩阵行数变多，模型才有“认识”新 token 的参数。类比：新增一个汉字，字典里就要多一行解释。

5. 论文扩完的完整词表长这样（论文图 2(b) 的 token 表，照抄记不住就截图）：

  • 编号 0–15：16 个虚拟原子 [1*]~[16*]（BRICS 切口标记）。
  • 编号 16–195：180 个功能团（苯环 c1ccccc1、卤素 Br Cl 等）。
  • 编号 196–197：片段起止 <BOF> / <EOF>。
  • 编号 198–199：分子起止 <BOM> / <EOM>。
  • 编号 200–131072：LLaMA 3.1 原始词表（约 13 万 token）——新增的 200 个化学 token 是追加在原始词表前面的。

6. 完整分子和片段分别怎么包（论文图 2(b) 示例）：完整分子用分子标记包：<BOM>NC(=O)CN1CCC(N)CC1<EOM>；片段用片段标记包：<BOF>[4*]CC(N)=O<EOF>。模型看到标记就知道"这是完整分子还是片段"。

7. 多组分怎么处理（论文 3.2 节末尾）：反应物/产物里的点 .（D2 学过）在分词时会被拆成多个独立组件，各自包上自己的起止标记——模型就分得清"一组分子"和"单个分子"。

训练循环 + LoRA + 显存

今天目标：看懂“模型是怎么被训练出来的”——一次训练循环的五步、loss 是什么、LoRA 为什么省显存、batch/梯度累积/epoch 怎么算，并亲手跑一次本地 smoke test。

这条线怎么串起来的：D5 知道 SMILES 怎么变成 token → 今天 D6 学这些 token 怎么被训练：一次循环五步、loss 怎么算、LoRA 怎么省显存 → D7 把实验规格定成制度。今天看懂的双任务 loss（两个方向各算一次再平均），D8 预训练和 D9 微调就是直接照搬。

学什么今天要懂的知识点

1. 训练五步循环：输入 → 预测 → 算 loss → 反向传播 → 更新参数。每一轮都让模型在“猜对”的方向上挪一点点，循环成千上万次。

2. 交叉熵 loss：衡量“预测结果 vs 正确答案”差多远，预测越偏 loss 越大。注意：loss 下降 ≠ 测试准确率高（可能过拟合或数据泄漏），两者要分开看。

3. LoRA：冻结基础模型绝大部分参数，只训练少量附加的小矩阵。类比：不重写整本书，只加一本“注释册”。省的是训练时的显存和算力。

4. 为什么 LoRA 仍要足够显存：模型本体还是要完整加载进显存；LoRA 只省了优化器状态 / 梯度那部分开销。

5. batch / 梯度累积 / epoch：

  • batch：一次喂给模型 N 个样本。
  • 梯度累积：攒 K 个 batch 的梯度再更新一次 → 有效 batch = N × K。
  • epoch：整个训练集完整走一遍。
计算题：2 卡 × 每卡 batch 2 × 累积 8 = 有效 batch 32。

6. 参数差异要记录：论文附录写学习率 1e-4、每卡 batch 2；仓库 conf/train_ChemDual.yaml 写 5e-5、每卡 batch 3。未确认作者最终配置前，不能把任何一方直接当“完全论文设置”。

7. 论文的 loss 长什么样（论文 3.3 节公式 5/6，通俗版）：

  • 模型对下一个 token 算出一个概率分布 softmax(z)（z 是模型输出的打分）；
  • 交叉熵 loss = -log(正确答案那个 token 的概率)——模型越觉得正确答案该出现，loss 越小；
  • 和 C 里 printf 的"把每个位置拼对"一样，模型是一格一格预测整个 SMILES 的。

8. "双任务"在代码里就是两个方向各算一次 loss（论文公式 7/8）：

  • 预训练损失 L_pt：分子→片段 和 片段→分子 两条样本各算一次 loss，再取平均；
  • 微调损失 L_ft：反应物→产物 和 产物→反应物 同理。
  • 一句话：正向反向一起学 = 两条样本进同一个 batch，总 loss 是两者平均。

9. 双任务到底有没有用——论文自己的证据（论文图 1(c)）：加双任务学习后，LLaMA 的反应预测 Exact 从 66.6% → 72.9%（+6.3%），ChemDual 从 76.6% → 86.9%。这不是玄学，是论文实测的涨分——你 D10 的对照组就是在复刻这个对比。

第一阶段训练：分子 ↔ 片段

今天目标：跑通论文第一阶段——让模型同时学“分子→片段”和“片段→分子”两个方向，并学会保存/理解 checkpoint。有没有 GPU 走两条不同的路，都要跑通。

这条线怎么串起来的：D7 定好实验规格 → 今天 D8 跑论文第一阶段：用 D3 造的分子-片段数据做预训练（分子↔片段双任务，就是 D6 公式 7 的 L_pt）→ D9 加载今天的 checkpoint 做第二阶段微调。今天跑通的流程，是明天 SFT 的起点。

学什么今天要懂的知识点

1. 第一阶段双任务：同时训练“分子→片段”和“片段→分子”两个方向——这是论文 dual-task 的第一组，让模型学会“分子和片段怎么互相转换”。

2. checkpoint 是什么：训练中间保存的状态（模型权重 + 优化器状态），可以恢复续训，是复现和后续微调的基础。类比：游戏存档——存了档，下次接着玩。

3. 数据装载与 label：训练前要确认——数据能正确读进来、每条的 label（该生成的答案）是对的、样本长度在模型能处理的范围内。

4. 今天跑的就是论文公式 7（论文 3.3 节）：预训练损失 L_pt 的样本对是 (M, F)/(F, M)——分子↔片段，和你 D3 造的"一次切分=一条样本"直接对应。训练数据规模：论文用 4.4M 条，你本地无 GPU 就用小样本跑通流程。

5. 为什么预训练不能省（论文图 4 消融）：跳过预训练直接微调（ChemDual w/o pre）在反应预测和逆合成上全部指标掉分——预训练让模型先学会"分子和片段怎么互相转换"，后面的反应任务才能学得动。这就是为什么 D8 是独立的一天，而不是直接跳到 D9。

评估指标

今天目标：学会用 5 个指标给预测打分——Exact、Validity、BLEU、Levenshtein、指纹相似度，并记住两个大坑：脚本打印的 Accuracy ≠ 论文的 EXACT。

这条线怎么串起来的：D11 存好预测文件 → 今天 D12 用 5 个指标给它打分（这就是论文表 1 那些列）→ D13 拿着分数看模型错在哪。今天学清楚每个指标"严在哪、松在哪"，才能看懂论文数字、也才不会被脚本的假 Accuracy 骗。

学什么今天要懂的知识点

五个指标，从“最严”到“最松”：

  • Exact：答案完全一样才算对（逐字比对，错一个字符都不算）。
  • Validity：预测能否解析成分子（MolFromSmiles 不返回 None）。
  • BLEU：文本 n-gram 重合度（机器翻译常用的相似度）。
  • Levenshtein：编辑距离，字符串差几步变一致。
  • 指纹相似度：Morgan/MACCS/RDK 指纹 + Tanimoto 系数算结构有多像；相似度高 ≠ 答案正确。

两个必须记住的坑：

  • 原仓库化学脚本打印的 Accuracy 是“组分交集比例”（宽松的部分匹配），不能直接当成论文表里的严格 EXACT。
  • 细节规则要记录：多组分如何排序比较、预测如何规范化、无效（非法 SMILES）样本是否计入分母。

论文表 1 的七列就是这些指标：EXACT / BLEU / LEVENSHTEIN / RDK / MACCS / MORGAN / VALIDITY——你学的 5 个指标全部上场（三个指纹相似度是三种指纹算同一类相似度）。ChemDual 反应预测那行：EXACT 0.869、BLEU 0.991、Levenshtein 2.099、三个 FTS 0.96+、VALIDITY 0.996——对照着看每个指标在说什么。

USPTO-50K 那边用的 Top-k（论文表 2）：逆合成允许模型给前 k 个候选答案，Top-1 46.25 / Top-3 60.14 / Top-5 66.95 / Top-10 77.42——"前 k 个里有没有对的"是逆合成的常见评估，和表 1 的 EXACT 不是一回事。

def exact(label, predict):
    """严格 Exact：逐字符完全一致才算对"""
    return 1 if label == predict else 0

def component_overlap(label, predict):
    """组分部分重合：按点 . 拆组分，算匹配组分的比例"""
    a = set(label.split("."))
    b = set(predict.split("."))
    return len(a & b) / max(len(a), len(b), 1)

cases = [
    ("CC.O", "CC.O"),        # 完全相同
    ("CC.O", "CC"),          # 预测少了水组分
    ("c1ccccc1", "c1ccccc1C"),  # 预测多了个甲基
]
for label, predict in cases:
    print(f"label={label:10} predict={predict:10} "
          f"Exact={exact(label, predict)} 交集={component_overlap(label, predict)}")

预期看到什么：三行输出——例 1 两者都是 1；例 2 Exact=0 但交集=0.5；例 3 Exact=0 且交集=0（苯环不是点分隔组分）。这就是脚本打印的 Accuracy（交集比例）和论文 EXACT 不是一回事的直接演示。

今天目标：看看模型到底错在哪（误差分析），并理解“删掉一个组件看掉多少分”（消融）怎么证明组件有用；没有真实训练时，只列缺项、不编造。

学什么今天要懂的知识点

1. 消融（ablation）：删掉某个组件（比如删掉反向任务）看性能掉多少，用来证明该组件有用。类比：拆掉自行车的链条，看它还跑不跑得动。

2. 误差分类（常见三类）：

  • 无效 SMILES：预测根本解析不成分子。
  • 组分漏掉：产物有多个组分，只预测出一部分。
  • 近似但不同：结构很像，但不是正确答案。

3. 分子对接（docking）：如果要复现论文的对接实验，还需要受体结构、网格设置等材料；前两周优先做预测实验，对接先列缺项、作为后续工作。

4. 论文怎么做"看错在哪"（论文 5 节可视化）：作者用 t-SNE 把模型的输入表示投影到二维，8 类反应样本在 ChemDual 里簇更紧凑、在 LLaMA 里更散——"学到的化学知识更分明"，这就是误差分析之外的正向证据。

5. 论文的分子对接案例（可作 D14 报告的例子）（论文 5 节 + 图 6）：选药物分子 CHEMBL419018 → BRICS 拆片段 → ChemDual 重组出新分子 TOP1 → 与 MAP2 蛋白对接得分 -8.3 kcal/mol，形成 3 个氢键（ARG-417、TYR-383、LEU-18）——说明模型生成的分子不但合法，还能和真实靶点结合，这是论文"能用于药物设计"的最终证据链。

6. 论文的消融三组对照（论文 4.3）：w/o dual（删掉反应/逆合成对）、w/o pre（删掉预训练）、LLaMA w/ dual（只加双任务不加预训练）——你 D10 设计的对照组就是其中"w/o dual"的最小版，D14 报告里要能说清你复刻了哪一组。
