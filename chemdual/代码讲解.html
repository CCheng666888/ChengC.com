代码逐行讲解：D2 · SMILES 与 RDKit

配套 notebook 里 D2 的四段代码，逐行告诉你"这一行在干嘛、为什么这样写"。打开 notebook 对照着看，看完一段回来勾掉一段。会用 C 的话，很多地方我都用 C 做了对照。

第 1 步 · 10 条 SMILES 画图 第 2 步 · 3 条无效 SMILES 第 3 步 · 成功率 + 写日志 第 4 步 · 核对两个测试 JSON

第 1 步10 条有效 SMILES，画出分子

from rdkit import Chem
from rdkit.Chem import Draw

smiles_list = [
    "CCCCO",          # 直链：丁醇
    "CCCCCC",         # 直链：己烷
    "CC(C)(C)O",      # 分支：叔丁醇
    "CC(C)CC",        # 分支：异戊烷
    "C1CCCCC1",       # 环：环己烷
    "c1ccccc1",       # 环：苯
    "c1ccncc1",       # 环：吡啶
    "CC(=O)O",        # 直链+羧基
    "CC.O",           # 多组分：乙醇+水
    "c1ccccc1.CCO",   # 多组分：苯+乙醇
]
mols = [Chem.MolFromSmiles(s) for s in smiles_list]
print("有效", sum(1 for m in mols if m is not None), "/", len(mols))
Draw.MolsToGridImage(mols, molsPerRow=4, subImgSize=(300, 220))
代码在干嘛（通俗版）
from rdkit import Chem导入 RDKit 的 Chem 模块。RDKit 是化学的"标准库"：Chem.MolFromSmiles 这种"读分子"的函数都在里面。相当于 C 里 #include 一个头文件。
from rdkit.Chem import Draw再导入画图模块 Draw，最后一行画分子图就靠它。
smiles_list = [...]一个装着 10 条文本的列表（C 里就是字符串数组）。# 后面是注释。10 条故意覆盖四种结构：直链、分支、环、多组分——正好对应论文里分子的四种常见形态。
mols = [Chem.MolFromSmiles(s) for s in smiles_list]列表推导式：把 10 条文本 逐条 喂给 MolFromSmiles，得到 10 个分子对象。等价于 C 的 for 循环，只是 Python 一行写完。
Chem.MolFromSmiles(s)核心函数：文本 → 分子。把 SMILES 字符串解析成一个内部的分子结构（原子、键、环）。解析不了就返回 None（后面第 2 步专门测这个）。
sum(1 for m in mols if m is not None)数一数有几个不是 None（= 解析成功）。if 过滤掉失败项，每个成功项贡献 1。这就是"解析成功率"的分母来源。
Draw.MolsToGridImage(mols, molsPerRow=4, ...)把 10 个分子画成 4 个一行的网格图。看到图 = 解析成功 + 能画结构，第 1 步验收达成。
为什么要会这个：论文从 ChEMBL 库里拿 20M 条 SMILES，第一步就是拿 RDKit 解析过滤——MolFromSmiles 解析不出来的，直接当垃圾数据扔掉（论文 3.1 节数据预处理第 2 条）。你刚学的这个函数，就是论文数据流水线的第一道闸门。

第 2 步3 条无效 SMILES，理解"为什么无效"

bad = {
    "CCC(O":   "括号不闭合：有 ( 没有对应的 )",
    "C1CCCCC": "环没闭合：C1 开环标记没遇到第二个 1",
    "c1ccccc": "芳香环缺原子：苯环要 6 个 c，这里只有 5 个",
}
for s, why in bad.items():
    print(f"{s:8} -> {Chem.MolFromSmiles(s)}   原因：{why}")
代码在干嘛（通俗版）
bad = { "CCC(O": "括号不闭合：..." , ... }一个字典：键是"故意写错的 SMILES"，值是"它为什么错"的人话解释。字典 = C 里"键值对"的表。
for s, why in bad.items()遍历字典，每次取出一个键 s 和一个值 why。相当于 C 的 for 循环访问数组，只是同时拿到"文本"和"原因"两样东西。
print(f"{s:8} -> {Chem.MolFromSmiles(s)} 原因：{why}")f"..." 是格式化字符串：把 {...} 里的变量直接算好填进文字——相当于 C 的 printf("%s", s)。:8 表示占 8 个字符宽度对齐。Chem.MolFromSmiles(s) 在这里现场解析，输出 None 就是失败。
None（运行结果）三条全是 None，说明三条都是非法 SMILES。RDKit 还会往日志里打一句 SMILES Parse Error: ...，那句英文就是失败原因的直接证据。
SMILES日志报错人话
CCC(Oextra open parentheses开了一个 ( 却始终没有 ) 关回来——括号不配对。
C1CCCCCunclosed ringC1 声明"这里开一个环"，但直到结尾都没遇到第二个 1 来关环。
c1cccccunclosed ring芳香环（小写 c）至少要 6 个原子，这里只有 5 个，环没封口。
为什么专门测无效：论文的 VALIDITY 指标就是"生成结果能不能被 RDKit 解析"。模型答了一串 CCCCCCC( 这种垃圾，VALIDITY 直接判 0。你在这里学会"什么是不合法"，后面看评估脚本才能看懂它在判什么。

第 3 步解析成功率 + 写进实验日志

good = ["CCCCO", "CCCCCC", "CC(C)(C)O", "CC(C)CC", "C1CCCCC1",
        "c1ccccc1", "c1ccncc1", "CC(=O)O", "CC.O", "c1ccccc1.CCO"]
valid = sum(1 for s in good if Chem.MolFromSmiles(s) is not None)
total = len(good) + 3          # 3 = 第 2 步的三条无效
print(f"解析成功率：{valid}/{total} 条有效（{valid/total:.0%}）")

from pathlib import Path
log = Path.cwd()
if log.name == "reproduce":
    log = log.parent
log = log / "reproduce" / "实验日志.md"
with open(log, "a", encoding="utf-8") as f:
    f.write("\n## 2026-10-17 · D2\n")
    f.write("- 10 条有效 SMILES 全部解析并绘图（直链/分支/环/多组分）\n")
    f.write("- 无效验证：3 条均返回 None（括号不闭合 / 环未闭合 / 芳香环缺原子）\n")
    f.write(f"- 解析成功率：{valid}/{total}\n")
print("已写入", log)
代码在干嘛（通俗版）
good = [...]10 条有效 SMILES 单独放一个列表——和第 1 步重复没关系，这里是"为了统计而单独拎出来"。
valid = sum(...)和前面一样，数出 10 条里成功解析几条（应该全成功 = 10）。
total = len(good) + 3总条数 = 10 有效 + 3 无效。成功率的分母。用 len(good) 而不是写死 10，是为了代码能复用。
f"{valid/total:.0%}".0% 把小数格式化成百分比且保留 0 位小数：10/13 → 77%。相当于 C 里 printf("%.0f%%", ...)。
from pathlib import Path导入路径工具。Path 就是"文件路径"对象，比 C 里拼字符串路径方便得多。
log = Path.cwd()cwd = current working directory，当前工作目录（notebook 运行时所在文件夹）。
if log.name == "reproduce": log = log.parent防呆处理：如果当前目录正好叫 reproduce，就退回上一级。目的是无论 notebook 在哪启动，都能定位到 reproduce/实验日志.md 这个固定位置。
log = log / "reproduce" / "实验日志.md"/ 在 Path 里是"拼接路径"（不是除法！）。最终得到完整路径：...\ChemDual\reproduce\实验日志.md。
with open(log, "a", encoding="utf-8") as f:打开文件追加写入。"a" = append，不清空原内容、只往末尾加（C 里对应 fopen(..., "a")）。encoding="utf-8" 保证中文不乱码。用 with 会自动关闭文件，不用手动 close。
f.write(...)把当天记录逐行写进日志。四行分别是：改了什么 / 跑了什么 / 看到了什么（成功率）。
print("已写入", log)打印最终路径，让你去确认文件真的写了。
为什么要写日志：D14 的科研复现报告要求"每个数字都能指回原始文件"。现在写的每一行，都是两周后报告的证据。日志格式固定为四件事：改了什么 / 跑了什么命令 / 看到了什么 / 下一步阻碍，每天 15 分钟就够。

第 4 步核对两个测试 JSON

import json
from pathlib import Path

root = Path.cwd()
if root.name == "reproduce":
    root = root.parent
for name in ["ChemDual_fragment_test.json", "ChemDual_recombination_test.json"]:
    rows = json.loads((root / "dataset" / name).read_text(encoding="utf-8"))
    print(name, "条数:", len(rows), "字段:", sorted(rows[0].keys()))
代码在干嘛（通俗版）
import json导入 JSON 处理模块。JSON 是存数据的标准文本格式（类似 C 的 struct 序列化后的文本）。
root = Path.cwd() ...同上一步的防呆逻辑：无论从哪启动，都定位到项目根目录（...\ChemDual\）。
for name in [...两个文件名...]循环处理两个测试文件：fragment_test（分子拆片段测试）和 recombination_test（片段拼分子测试）——正好对应论文双任务的预训练方向。
json.loads(...)把文件里的 JSON 文本解析成 Python 数据（列表）。read_text(encoding="utf-8") 先读成字符串，json.loads 再解析。
len(rows)列表长度 = 数据条数。应该输出 1000。
sorted(rows[0].keys())取第一条数据的字段名并排序。应该输出 ['input', 'instruction', 'output']。rows[0] 就是第一条（C 里 rows[0]）。
三个字段分别是什么：instruction = 给模型的指令（"请给出反应物"这类提问模板），input = 输入分子/片段，output = 标准答案。这三段拼起来就是一条完整的训练/测试样本，和论文图 3 的模板一一对应。核对目的：确保测试集没被污染、字段没改名——数据可信，后面所有分数才可信。
